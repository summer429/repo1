手機告警測試

點擊按鈕展開手把手流程：先在手機 App 打開推播，再發派會刻意失敗的 Agent 任務。可用基本測試確認有推播，再用「時間戳記驗證」對照這一次的時間與代碼是否出現在手機端。

測試手機告警

完整路徑：手機 App 允許通知 → 發派會刻意失敗的 Agent 任務 → Agent 在雲端或筆電跑出告警並結束這一輪 → 手機立刻收到 App 推播。點通知可回到同一個 Agent。

步驟 1．手機端 App 設定

  1. 在 iPhone 或 iPad 從 App Store 安裝 Cursor（iOS／iPadOS 26.0 以上）。Android 請用 Chrome 開啟 cursor.com/agents，再點「Install App」裝成 PWA。
  2. 用與電腦相同的 Cursor 帳號登入。公司若要求 SSO，就走 SSO。
  3. App 第一次詢問通知時按允許。若當時按了稍後，到手機「設定 → 通知 → Cursor」打開「允許通知」，並打開鎖定畫面、通知中心、橫幅與聲音。
  4. 同一頁打開 Live Activities（鎖定畫面與動態島最多可同時追蹤 8 個 Agent）。
  5. 關閉勿擾，或把 Cursor 加進允許通知的 App。背景 App 重新整理維持開啟。
  6. 帳號須為含 Cloud Agents 的方案（Pro、Pro+、Ultra、Teams、Enterprise）。隱私模式請使用 Privacy Mode；Legacy Privacy Mode 無法在手機啟動 Agent。
  7. 打開 App，確認看得到要測試的儲存庫與分支。Teams 帳號請登入同一個團隊，Agent 清單才會對得上。

送出任務後把 App 切到背景或鎖定螢幕。App 留在前景時，系統通常只更新畫面，橫幅推播會晚一點才出現。

步驟 2．選定 Agent 跑在雲端或筆電

雲端

  1. 在電腦的 Agents 視窗，或開啟 cursor.com/agents。
  2. 輸入框下方選 Cloud，指定這個儲存庫與分支。
  3. 也可以直接在手機 App 選儲存庫後送出下面的測試任務。雲端機器會繼續跑，手機鎖定也沒關係。

筆電（Remote Control）

  1. 電腦安裝 Cursor 3.9.8 或更新版本。
  2. Agents 視窗開啟 Settings → Agents → Remote Control。需要的話一併打開「Keep this computer awake」。
  3. Teams／Enterprise 請管理員先到 Dashboard → Cloud Agents → Self-Hosted 啟用 Remote Control。
  4. 在本機 Agent 輸入框執行 /remote-control，下一則訊息再貼上步驟 3 的任務。
  5. 工具指令跑在這台電腦上，所以電腦要保持開機、聯網、不要睡眠。工作階段會出現在手機收件匣。

步驟 3．發派會刻意觸發錯誤的任務（基本測試）

把下面整段貼進 Agent 後送出。它只執行一個必定以 exit code 2 結束的指令，然後立刻停止，讓這一輪以告警狀態結束。Cursor 會在 Agent 結束這一輪時發送推播。

【手機告警測試｜請刻意失敗並立刻結束】

這是一則推播測試，請嚴格只做下面三件事，然後結束這一輪：

1. 在終端機執行這段一定會失敗的指令（不要改寫、不要重跑）：
   node -e "console.error('MOBILE_ALERT_TEST: intentional failure'); process.exit(2)"

2. 確認行程以 exit code 2 結束。若環境沒有 node，改執行：
   python3 -c "import sys; sys.stderr.write('MOBILE_ALERT_TEST: intentional failure\n'); sys.exit(2)"

3. 不要修復、不要重試、不要修改任何檔案、不要 commit、不要開 pull request。
   立刻停止，並用下面這段當回覆的第一行：

   【告警】手機推播測試：刻意觸發的指令失敗（exit code 2）

   接著只列出三行：失敗指令、exit code、錯誤訊息原文。

步驟 3B．第二則驗證：帶時間戳記的告警訊息

若基本測試已通過，再用這則確認「這一次」推播有到手機。腳本每次執行都會產生新的台北時間與驗證代碼；請把回覆第一行的時間與代碼，和鎖定畫面／通知中心、Agent 內文對起來。

本機可先預覽輸出（一定 exit 2）：

node SA/checks/00-mobile-alert-timestamp.js

對照重點：stderr 會有 VERIFY_TOKEN、TIMESTAMP_TAIPEI；Agent 回覆第一行應含同一組時間與代碼。手機點開同一 Agent，內文也要看得到這兩項。

【手機告警驗證｜時間戳記｜請刻意失敗並立刻結束】

這是一則推播驗證，請嚴格只做下面四件事，然後結束這一輪：

1. 先更新到最新 main（不要改業務檔）：
   git fetch origin
   git checkout origin/main -- SA/checks/00-mobile-alert-timestamp.js
   ls -la SA/checks/00-mobile-alert-timestamp.js

2. 在專案根目錄執行（不要改寫、不要重跑）：
   node SA/checks/00-mobile-alert-timestamp.js

3. 確認行程以 exit code 2 結束。從 stderr 讀出：
   - VERIFY_TOKEN（例如 MAT-12345678）
   - TIMESTAMP_TAIPEI（Asia/Taipei）
   - TIMESTAMP_UTC
   若環境沒有 node，或找不到腳本，改執行：
   python3 -c "from datetime import datetime, timezone, timedelta; import sys; now=datetime.now(timezone.utc); taipei=now.astimezone(timezone(timedelta(hours=8))).strftime('%Y/%m/%d %H:%M:%S'); token='MAT-'+str(int(now.timestamp()*1000))[-8:]; sys.stderr.write('ALERT_00_MOBILE_TIMESTAMP\nMOBILE_ALERT_TIMESTAMP_TEST: intentional failure with timestamp\nVERIFY_TOKEN='+token+'\nTIMESTAMP_UTC='+now.isoformat().replace('+00:00','Z')+'\nTIMESTAMP_TAIPEI='+taipei+' (Asia/Taipei)\n'); sys.exit(2)"

4. 不要修復、不要重試、不要修改任何檔案、不要 commit、不要開 pull request。
   立刻停止。回覆第一行必須是（把實際值填進去，不要用範例字串）：

   【告警】手機推播驗證｜{TIMESTAMP_TAIPEI}｜代碼 {VERIFY_TOKEN}

   接著只列出：失敗指令、exit code、VERIFY_TOKEN、TIMESTAMP_TAIPEI、TIMESTAMP_UTC、stderr 原文（含 ALERT_00_MOBILE_TIMESTAMP）。
   若是找不到模組（exit 1），先回報 git rev-parse HEAD 與 ls SA/checks/ 結果後結束。

步驟 4．確認手機立刻收到推播

  1. 送出後立刻鎖定手機，或把 Cursor App 切到背景。
  2. 雲端或筆電上的 Agent 跑完那個失敗指令，回覆以「【告警】…」開頭並結束這一輪。
  3. 鎖定畫面應出現 Cursor 推播；若有 Live Activity，狀態會從進行中變成這一輪已結束。
  4. 點推播應打開同一個 Agent。基本測試看 MOBILE_ALERT_TEST: intentional failure；時間戳記驗證還要對到同一組 TIMESTAMP_TAIPEI 與 VERIFY_TOKEN（例如 MAT-…）。

你應該看到：Agent 在雲端或筆電跑出告警 → 手機立刻收到 App 推播通知。時間戳記驗證時，通知／內文的時間與代碼與 stderr 一致，即可確認是「這一次」成功送到手機。

若鎖定畫面沒有橫幅，依序檢查：

  • 「設定 → 通知 → Cursor」的允許通知、橫幅、鎖定畫面為開啟。
  • 這次任務是 Cloud，或已用 /remote-control 交給手機。只留在本機、沒有交出的 Agent 不會進入手機收件匣。
  • 手機與電腦是同一個帳號；Teams 要在同一個團隊。
  • 電腦在 Remote Control 測試時保持醒著且有網路。
  • 打開 App 的收件匣，確認該 Agent 已以告警內容結束。推播對應的是「這一輪結束」。
  • 時間戳記驗證：若手機內文沒有 VERIFY_TOKEN，可能是舊輪次推播；重新複製步驟 3B 任務再送一次，用新代碼對照。

專案告警情境清單

依目前 ECIF 原型整理，供 Cursor Agent 任務失敗時推播。各情境規劃一支可驗證的檢查腳本；失敗時寫出情境代碼並以 exit code 2 結束，不必等真後端。01、02 已完成，其餘依優先順序逐項補上。

撰寫順序：高優先（側欄死連結 → 登入流程斷鏈 → 查詢無真實結果）→ 中（限閱戶、權限遮罩、缺頁回歸）→ 低（靜態資源、Prompt／原型不同步）。下一支要寫：SA/checks/03-query-not-wired.js

優先 情境 觸發條件（範例） 為什麼值得告警 規劃檢查腳本 腳本要驗什麼 狀態
高 側欄死連結 Agent 補齊缺頁後，main.html 仍指向不存在的 *.html 多數選單目前會 iframe 載入失敗 SA/checks/01-sidebar-dead-links.js 掃描 main.html 的 data-page，缺檔則失敗 已撰寫
高 登入流程斷鏈 帳密正確後未導向 main.html 原型核心路徑不通 SA/checks/02-login-redirect.js 成功登入分支沒有 location／href 指向 main.html 則失敗 已撰寫
高 查詢無真實結果 「查詢」仍只 console.log、表格永遠寫死王小明 查詢功能形同未接 SA/checks/03-query-not-wired.js submit 只有 log、結果仍硬編碼範例列則失敗 待撰寫
中 限閱戶未提示 查詢結果為限閱戶卻沒有提示／未記錄行為 prompts.html 需求有寫、頁面沒做 SA/checks/04-restricted-user-hint.js basic_data_query.html 找不到限閱戶提示或紀錄則失敗 待撰寫
中 權限遮罩失效 非授權欄位（身分證、電話等）未隱藏／遮罩 個資合規風險 SA/checks/05-pii-mask.js 查詢結果明文輸出身分證／電話且無遮罩邏輯則失敗 待撰寫
中 缺頁回歸 CI／煙霧測試發現 account_query、customer_history、報表頁等仍 404 側欄規劃了 10 頁、實作只有 1 頁 SA/checks/06-missing-pages.js 側欄列出的頁面檔案必須都存在，缺一則失敗 待撰寫
低 靜態資源未引用 style.css 未被任何 HTML 引用卻被當成已套用 樣式預期與實際不一致 SA/checks/07-unused-style-css.js 沒有 HTML link 到 style.css 則失敗 待撰寫
低 Prompt／原型不同步 prompts.html 需求與實際頁面欄位不一致 AI 再生成時會走偏 SA/checks/08-prompt-prototype-drift.js 比對 prompt 必填欄位（如客戶 ID）與查詢頁實際欄位，不一致則失敗 待撰寫

腳本約定（撰寫時共用）

  • 目錄：SA/checks/；檔名與上表一一對應。
  • 執行環境以 Cloud Agent（Linux）為準，使用 Node，本機也可跑。
  • 通過：exit 0。失敗：stderr 先輸出情境代碼（例如 ALERT_01_SIDEBAR_DEAD_LINKS），再 exit 2。
  • 只讀檢查，不修改業務檔、不 commit、不開 PR。Agent 任務失敗即可推播。
  • 實作方式：Cursor Automations 設「Agent 任務失敗就推播」；逐項補腳本後，把對應檢查指令貼給 Cloud Agent。

01 側欄死連結：本機執行、通過、觸發告警

在專案根目錄執行：

node SA/checks/01-sidebar-dead-links.js

通過檢核（exit 0）：為 main.html 每個 data-page 補上對應 HTML 檔（哪怕是空白頁），或拿掉仍指向缺檔的側欄項目。再跑同一指令，stdout 應全是 OK，最後一行 PASS。

觸發告警（exit 2）：維持現況（多數側欄頁不存在），把下面任務貼給 Cloud Agent。Agent 只准跑檢查、不准修檔；失敗後這一輪結束，手機會收到推播。

注意：Cloud Agent 可能從舊的 Build 快照開機，工作區會落後 GitHub。任務裡必須先 git pull。也可到 Dashboard → Environments → Build Settings，開啟 Update stale builds，並把 Staleness threshold 設成 0。

【專案告警檢查｜01 側欄死連結】

請只做下面四件事，然後結束這一輪：

1. 先更新到最新 main（不要改業務檔）：
   git fetch origin
   git checkout origin/main -- SA/checks/01-sidebar-dead-links.js
   ls -la SA/checks/01-sidebar-dead-links.js

2. 在專案根目錄執行（不要改寫、不要重跑）：
   node SA/checks/01-sidebar-dead-links.js

3. 確認行程結束碼。若不是 0，視為檢查失敗。

4. 不要修復、不要補頁、不要修改任何業務檔案、不要 commit、不要開 pull request。
   立刻停止。若 exit code 為 2，回覆第一行：

   【告警】側欄死連結：main.html 指向不存在的頁面

   接著只列出：失敗指令、exit code、stderr 原文（含 ALERT_01_SIDEBAR_DEAD_LINKS）。
   若是找不到模組（exit 1），先回報 git rev-parse HEAD 與 ls SA/checks/ 結果後結束。

02 登入流程斷鏈：本機執行、通過、觸發告警

在專案根目錄執行：

node SA/checks/02-login-redirect.js

通過檢核（exit 0）：在 login.html 成功登入分支（帳密皆為 ebiz）加入導向，例如 location.href = 'main.html';。再跑同一指令，stdout 應有 OK 與最後一行 PASS。

觸發告警（exit 2）：維持現況（成功只 alert、未導向），把下面任務貼給 Cloud Agent。Agent 只准跑檢查、不准修檔；失敗後這一輪結束，手機會收到推播。

注意：Cloud Agent 可能從舊的 Build 快照開機。任務裡必須先把檢查腳本從 origin/main 取出；或到 Dashboard 把 Staleness threshold 設成 0。
