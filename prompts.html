Slack 告警測試

點擊按鈕展開手把手流程：Slack 已連接後，在 Automations 啟用 Send to Slack 並指定 channel，再發派會刻意失敗的 Agent 任務。可用基本測試確認 channel 有訊息，再用「時間戳記驗證」對照這一次的時間與代碼。

測試 Slack 告警

完整路徑：Slack 已連接 → Automations 啟用 Send to Slack 並指定 channel（例如 #cursor-alerts）→ 發派會刻意失敗的 Agent 任務 → Agent 結束這一輪並把告警貼到該 channel。在 Slack 對照訊息內容與 Agent 內文。

步驟 1．Slack 與 Automations 設定

  1. 確認 Cursor Integrations 已連接 Slack（Dashboard → Integrations）。若尚未安裝，到 Integrations 完成 Connect。
  2. 在 Slack 目標 channel（建議公開頻道，例如 #cursor-alerts）執行 /invite @Cursor，讓 Cursor bot 加入。
  3. 開啟 cursor.com/automations，新建或編輯既有告警 Automation。
  4. 工具區啟用 Send to Slack，目標選「指定 channel」，填入剛才邀請 bot 的頻道。
  5. Repository 指定 summer429/repo1（分支 main）。觸發可用 Webhook（方便重測）或 Scheduled。
  6. Prompt 需要求：檢查失敗（exit 2）時，用 Send to Slack 把告警摘要（含情境代碼、VERIFY_TOKEN、執行連結）貼到指定 channel；不要修檔、不要開 PR。
  7. Save 並 Activate。若用 Webhook，儲存後複製 webhook URL 與 API key 供重測。

與手機推播的差異：告警主路徑改為 Slack channel（可讀全文、可對 token）。手機 App 推播若仍開啟可當輔助，但驗證以 Slack 訊息為準。

步驟 2．選定 Agent 跑在雲端或 Automation

Cloud Agent

  1. 在電腦的 Agents 視窗，或開啟 cursor.com/agents。
  2. 輸入框下方選 Cloud，指定這個儲存庫與分支。
  3. 貼上步驟 3 的任務；結束後到 Slack channel 確認告警訊息。

Automations

  1. 在 Automations 頁面對該規則按 Test Run，或 POST webhook。
  2. 確認工具已勾選 Send to Slack，且 channel 正確。
  3. 跑完後同一 channel 應出現含告警代碼的訊息與 Agent 連結。

步驟 3．發派會刻意觸發錯誤的任務（基本測試）

把下面整段貼進 Agent（或寫進 Automation Prompt）後送出。它只執行一個必定以 exit code 2 結束的指令，然後立刻停止，並把告警送到 Slack channel。

【Slack 告警測試｜請刻意失敗並立刻結束】

這是一則 Slack channel 告警測試，請嚴格只做下面四件事，然後結束這一輪：

1. 在終端機執行這段一定會失敗的指令（不要改寫、不要重跑）：
   node smoke-test.js
   若沒有 smoke-test.js，改執行：
   node -e "console.error('MOBILE_ALERT_TEST: intentional failure'); process.exit(2)"

2. 確認行程以 exit code 2 結束。若環境沒有 node，改執行：
   python3 -c "import sys; sys.stderr.write('MOBILE_ALERT_TEST: intentional failure\n'); sys.exit(2)"

3. 若有 Send to Slack 工具：把告警貼到設定的 channel（例如 #cursor-alerts）。訊息至少包含：
   【告警】Slack 測試：刻意觸發的指令失敗（exit code 2）
   失敗指令、exit code、錯誤訊息原文、本次 Agent 連結。

4. 不要修復、不要重試、不要修改任何檔案、不要 commit、不要開 pull request。
   立刻停止，並用下面這段當回覆的第一行：

   【告警】Slack 測試：刻意觸發的指令失敗（exit code 2）

   接著只列出：失敗指令、exit code、錯誤訊息原文、是否已送 Slack。

步驟 3B．第二則驗證：帶時間戳記的告警訊息

若基本測試已通過，再用這則確認「這一次」告警有到 Slack。腳本每次執行都會產生新的台北時間與驗證代碼；請把回覆／Slack 訊息的時間與代碼對起來。

本機可先預覽輸出（一定 exit 2）：

node SA/checks/00-mobile-alert-timestamp.js

對照重點：stderr 會有 VERIFY_TOKEN、TIMESTAMP_TAIPEI；Agent 回覆與 Slack channel 訊息都應含同一組時間與代碼。

【Slack 告警驗證｜時間戳記｜請刻意失敗並立刻結束】

這是一則 Slack channel 告警驗證，請嚴格只做下面五件事，然後結束這一輪：

1. 先取出驗證腳本（不要改業務檔）：
   git fetch origin
   git checkout origin/main -- SA/checks/00-mobile-alert-timestamp.js 2>/dev/null \
     || git checkout origin/cursor/mobile-alert-timestamp-e391 -- SA/checks/00-mobile-alert-timestamp.js 2>/dev/null \
     || true
   ls -la SA/checks/00-mobile-alert-timestamp.js 2>/dev/null || echo "SCRIPT_MISSING_USE_FALLBACK"

2. 在專案根目錄執行（不要改寫、不要重跑）：
   若腳本存在：
   node SA/checks/00-mobile-alert-timestamp.js
   若腳本不存在或沒有 node，改執行：
   python3 -c "from datetime import datetime, timezone, timedelta; import sys; now=datetime.now(timezone.utc); taipei=now.astimezone(timezone(timedelta(hours=8))).strftime('%Y/%m/%d %H:%M:%S'); token='MAT-'+str(int(now.timestamp()*1000))[-8:]; sys.stderr.write('ALERT_00_MOBILE_TIMESTAMP\nMOBILE_ALERT_TIMESTAMP_TEST: intentional failure with timestamp\nVERIFY_TOKEN='+token+'\nTIMESTAMP_UTC='+now.isoformat().replace('+00:00','Z')+'\nTIMESTAMP_TAIPEI='+taipei+' (Asia/Taipei)\n'); sys.exit(2)"

3. 確認行程以 exit code 2 結束。從 stderr 讀出：
   - VERIFY_TOKEN（例如 MAT-12345678）
   - TIMESTAMP_TAIPEI（Asia/Taipei）
   - TIMESTAMP_UTC

4. 若有 Send to Slack 工具：把同一組 VERIFY_TOKEN、TIMESTAMP_TAIPEI、stderr 摘要與 Agent 連結貼到設定的 channel（例如 #cursor-alerts）。

5. 不要修復、不要重試、不要修改任何檔案、不要 commit、不要開 pull request。
   立刻停止。回覆第一行必須是（把實際值填進去，不要用範例字串）：

   【告警】Slack 驗證｜{TIMESTAMP_TAIPEI}｜代碼 {VERIFY_TOKEN}

   接著只列出：失敗指令、exit code、VERIFY_TOKEN、TIMESTAMP_TAIPEI、TIMESTAMP_UTC、stderr 原文（含 ALERT_00_MOBILE_TIMESTAMP）、是否已送 Slack。
   若連 fallback 都失敗，先回報 git rev-parse HEAD 與 ls SA/checks/ 結果後結束。

步驟 4．確認 Slack channel 收到告警

  1. 送出任務或觸發 Automation 後，打開目標 Slack channel（例如 #cursor-alerts）。
  2. Agent／Automation 跑完失敗指令後，回覆以「【告警】…」開頭並結束這一輪。
  3. channel 應出現 Cursor bot 訊息；基本測試看 MOBILE_ALERT_TEST: intentional failure 或 ALERT_SMOKE_TEST。
  4. 時間戳記驗證還要對到同一組 TIMESTAMP_TAIPEI 與 VERIFY_TOKEN（例如 MAT-…）。

你應該看到：Agent 跑出告警 → Slack channel 立刻出現含代碼的訊息。時間與代碼與 stderr／Agent 內文一致，即可確認是「這一次」成功送到 Slack。

若 channel 沒有訊息，依序檢查：

  • Automations 是否已 Activate，且工具 Send to Slack 已勾選、channel 選對。
  • 目標 channel 是否已 /invite @Cursor。
  • Prompt 是否明確要求失敗時呼叫 Send to Slack（僅靠手機推播不會自動進 Slack）。
  • 時間戳記驗證：若 Slack 沒有 VERIFY_TOKEN，重新複製步驟 3B 任務再送一次，用新代碼對照。

專案告警情境清單

依目前 ECIF 原型整理，供 Cursor Agent 任務失敗時以 Send to Slack 送到指定 channel。各情境規劃一支可驗證的檢查腳本；失敗時寫出情境代碼並以 exit code 2 結束，不必等真後端。01、02 已完成，其餘依優先順序逐項補上。

撰寫順序：高優先（側欄死連結 → 登入流程斷鏈 → 查詢無真實結果）→ 中（限閱戶、權限遮罩、缺頁回歸）→ 低（靜態資源、Prompt／原型不同步）。下一支要寫：SA/checks/03-query-not-wired.js

優先 情境 觸發條件（範例） 為什麼值得告警 規劃檢查腳本 腳本要驗什麼 狀態
高 側欄死連結 Agent 補齊缺頁後，main.html 仍指向不存在的 *.html 多數選單目前會 iframe 載入失敗 SA/checks/01-sidebar-dead-links.js 掃描 main.html 的 data-page，缺檔則失敗 已撰寫
高 登入流程斷鏈 帳密正確後未導向 main.html 原型核心路徑不通 SA/checks/02-login-redirect.js 成功登入分支沒有 location／href 指向 main.html 則失敗 已撰寫
高 查詢無真實結果 「查詢」仍只 console.log、表格永遠寫死王小明 查詢功能形同未接 SA/checks/03-query-not-wired.js submit 只有 log、結果仍硬編碼範例列則失敗 待撰寫
中 限閱戶未提示 查詢結果為限閱戶卻沒有提示／未記錄行為 prompts.html 需求有寫、頁面沒做 SA/checks/04-restricted-user-hint.js basic_data_query.html 找不到限閱戶提示或紀錄則失敗 待撰寫
中 權限遮罩失效 非授權欄位（身分證、電話等）未隱藏／遮罩 個資合規風險 SA/checks/05-pii-mask.js 查詢結果明文輸出身分證／電話且無遮罩邏輯則失敗 待撰寫
中 缺頁回歸 CI／煙霧測試發現 account_query、customer_history、報表頁等仍 404 側欄規劃了 10 頁、實作只有 1 頁 SA/checks/06-missing-pages.js 側欄列出的頁面檔案必須都存在，缺一則失敗 待撰寫
低 靜態資源未引用 style.css 未被任何 HTML 引用卻被當成已套用 樣式預期與實際不一致 SA/checks/07-unused-style-css.js 沒有 HTML link 到 style.css 則失敗 待撰寫
低 Prompt／原型不同步 prompts.html 需求與實際頁面欄位不一致 AI 再生成時會走偏 SA/checks/08-prompt-prototype-drift.js 比對 prompt 必填欄位（如客戶 ID）與查詢頁實際欄位，不一致則失敗 待撰寫

  • 目錄：SA/checks/；檔名與上表一一對應。
  • 執行環境以 Cloud Agent（Linux）為準，使用 Node，本機也可跑。
  • 通過：exit 0。失敗：stderr 先輸出情境代碼（例如 ALERT_01_SIDEBAR_DEAD_LINKS），再 exit 2。
  • 只讀檢查，不修改業務檔、不 commit、不開 PR。Agent 任務失敗後以 Send to Slack 送到指定 channel。
  • 實作方式：Cursor Automations 啟用 Send to Slack 並指定 channel；逐項補腳本後，把對應檢查指令貼給 Cloud Agent／寫進 Automation Prompt。

01 側欄死連結：本機執行、通過、觸發告警

在專案根目錄執行：

node SA/checks/01-sidebar-dead-links.js

通過檢核（exit 0）：為 main.html 每個 data-page 補上對應 HTML 檔（哪怕是空白頁），或拿掉仍指向缺檔的側欄項目。再跑同一指令，stdout 應全是 OK，最後一行 PASS。

觸發告警（exit 2）：維持現況（多數側欄頁不存在），把下面任務貼給 Cloud Agent。Agent 只准跑檢查、不准修檔；失敗後這一輪結束，Slack channel 應收到告警。

注意：Cloud Agent 可能從舊的 Build 快照開機，工作區會落後 GitHub。任務裡必須先 git pull。也可到 Dashboard → Environments → Build Settings，開啟 Update stale builds，並把 Staleness threshold 設成 0。

4. 不要修復、不要補頁、不要修改任何業務檔案、不要 commit、不要開 pull request。
   立刻停止。若 exit code 為 2：
   - 若有 Send to Slack：把告警貼到設定的 channel（含情境代碼與 Agent 連結）
   - 回覆第一行：

   接著只列出：失敗指令、exit code、stderr 原文（含 ALERT_01_SIDEBAR_DEAD_LINKS）、是否已送 Slack。
   若是找不到模組（exit 1），先回報 git rev-parse HEAD 與 ls SA/checks/ 結果後結束。
